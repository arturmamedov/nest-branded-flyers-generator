# Nest flyers: a staff login for the whole app (the editor, the art, the photos
# and the API). Paste this block at the TOP of the app's .htaccess, above the
# release's own https redirect. The preflight page prints it with this
# account's paths filled in (docs/deploy.md, step 3).
#
# It asks for the password over https only. Over http it answers 403 without
# asking, so the password never crosses the wire unencrypted, and if anything
# here is not understood Apache refuses rather than lets in. (A redirect in
# .htaccess is not enough on its own: Apache asks for the password before any
# .htaccess redirect runs.)
#
# Use the same user and password as basicAuth in config.php: config.php guards
# the API, this block everything else, and a staff member who passes only one
# of them is refused by the other.
#
# 1. The password file, one "user:hash" line per login. Put it OUTSIDE the web
#    root when your FTP login can reach such a folder (IONOS:
#    /homepages/NN/dNNNNNNNNN/nest-flyers.htpasswd); otherwise name it .htpasswd
#    in the app folder: Apache never serves a file whose name starts with .ht.
#    The preflight page prints the line; so does htpasswd on your own machine
#    (it ships with Apache and Laragon):
#        htpasswd -nbB staff "the-password"
# 2. Put that file's absolute path in AuthUserFile (the preflight page shows the
#    app folder's absolute path).
#
# Apache 2.4 ("Require expr" does not exist on 2.2).

AuthType Basic
AuthName "Nest flyers"
AuthUserFile /home/ACCOUNT/nest-flyers.htpasswd
<RequireAll>
    Require valid-user
    Require expr "%{HTTPS} == 'on' || %{HTTP:X-Forwarded-Proto} == 'https'"
</RequireAll>

# To let an office in without a password (still over https only), use this
# instead of the RequireAll block above:
#     <RequireAll>
#         <RequireAny>
#             Require ip 203.0.113.7
#             Require valid-user
#         </RequireAny>
#         Require expr "%{HTTPS} == 'on' || %{HTTP:X-Forwarded-Proto} == 'https'"
#     </RequireAll>

# Over http the lines above answer 403 before any redirect can run: this turns
# that 403 into the redirect to https://. <If> is allowed in .htaccess only
# where the host allows everything there (AllowOverride All); where it is not,
# every page answers an error (500, or IONOS's 403 page). Delete these three
# lines there: http:// visitors then get a plain 403, which is still safe.
<If "%{HTTPS} != 'on' && %{HTTP:X-Forwarded-Proto} != 'https'">
    ErrorDocument 403 https://%{HTTP_HOST}%{REQUEST_URI}
</If>
